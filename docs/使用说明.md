# 使用与维护

首次搭建请按 [从零搭建](从零搭建.md) 操作；手机提问请看 [日常使用指南](日常使用指南.md)。本页为部署后的维护手册。所有示例日期和地址都需要替换。

## 管理操作

Windows PowerShell 中，从仓库根目录运行：

```powershell
$workerUrl = 'https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev'
./scripts/health.ps1 -Url $workerUrl -Action status
./scripts/health.ps1 -Url $workerUrl -Action sync -Start '2026-10-23' -End '2026-10-29'
./scripts/health.ps1 -Url $workerUrl -Action export
./scripts/health.ps1 -Url $workerUrl -Action context -ContextFile ./examples/context.json
```

脚本从 `secrets/ADMIN_TOKEN.txt` 读取令牌。先把示例日期和安排改为自己的，再导入；相同 id 更新记录。不要把密钥贴进聊天。PowerShell 脚本可沿用已开启的简单 Windows 系统代理，也支持 `-Proxy http://127.0.0.1:PORT`；不会更改网络设置。

导出位于 `exports/`，默认是最近 7 个已结束自然日；可用 `-Start`、`-End` 指定，最多查询 90 天。手动同步每次最多 7 天，按周回补更早历史。即时工具默认包含今天，与默认导出的日期范围不同。

## 每周检查

检查 `status` 的采集尝试与发送状态，查看数据包中的 `latestAttempts`、`fetched_at`、有效天数和日期。`error` 是读取失败，`empty` 是源端无记录，不能填零。`/health` 仅说明服务存活。后台不能强制手机上传；缺失时先核对手机同步和 Google 中的记录。

`fetch_latest_health` 的 `busy` 表示另一次采集持有锁，返回的是归档；等待完成再重试一次。失败时明确标记归档数据日期。没有足够历史时，28 天窗口只是查询范围，不代表拥有 28 个有效样本。

周邮件默认关闭。核对首次采集后，设置 `wrangler.workflow.toml` 的 `WEEKLY_EMAIL = "true"` 并运行 `npm run deploy`。`POST /weekly-run` 可手动触发上一完整周，受开关与去重约束，需管理 Bearer。该操作会真实发信，请在需要验收时主动执行。

邮件 `needs_review` 或长期 `sending` 时，先核对 Gmail 已发送文件夹，再决定是否人工处理数据库中的发送保留记录。超时可能已经发出，系统不会盲目重试。单封 MIME 超过 4 MB 时用导出；周包是数据，不是 GPT 报告，也不会自动唤起 ChatGPT。

## OAuth 与更新

Google Testing 模式下，当前使用的范围可能使刷新令牌在 7 天后过期；长期运行应处理控制台发布/验证要求并重新授权。切到 Production 不代表已通过 Google 验证。见 [Google 令牌有效期](https://developers.google.com/identity/protocols/oauth2#expiration)。

重新授权使用：

```powershell
npm run workflow:setup -- authorize health oauth-client-health.json
npm run workflow:setup -- authorize gmail oauth-client-gmail.json
```

默认健康权限不含设备状态；如确需设备同步时间，在 Google Cloud 加入 `googlehealth.settings.readonly`，运行 `authorize health-device oauth-client-health.json`，同意全部原有与新增范围，再设置 `DEVICE_STATUS_ENABLED = "true"` 后部署。设备最近同步时间不能证明每个指标完整。

更新本地源码后：先读变更、备份数据、安装锁定依赖、执行类型检查和测试，再按新增迁移与配置要求处理。当前公开版需要在本地配置 `[vars]` 设置 `PUBLIC_ORIGIN` 为本实例的 HTTPS origin，才能使用 MCP OAuth。旧部署升级前也须填写；更换域名后须更新并重新连接 ChatGPT。不要把公开模板直接覆盖自己的真实配置。

## 备份与恢复

```powershell
New-Item -ItemType Directory -Force exports | Out-Null
pnpm exec wrangler d1 export DB --remote -c wrangler.workflow.toml --output exports/health-backup.sql
```

备份含健康数据，保存到自己控制的加密磁盘。恢复时先创建新的 D1，将备份导入新库，验证查询结果后再修改 Worker 绑定。D1 备份不包含 KV、Secrets、Gmail 和 ChatGPT 副本；这些需各自维护，令牌缺失可以重新授权。

## 停止、撤销与删除

停邮件：将 `WEEKLY_EMAIL` 改回 `"false"` 后部署。停采集：移除 Cron 后部署（即时工具仍可触发采集）。彻底停止需停用 Worker 或撤销 Google 授权。

删除前先停后台任务和外部连接，再由部署者删除对应 D1、三个 KV、Worker/Secrets，撤销 Google 第三方授权，清理本地 `exports/`、`secrets/` 与 Gmail/ChatGPT 中的副本。撤销权限不会自动删除历史，删除数据库也不会删除已经分享的副本。

访问密钥轮换要同步更新 Cloudflare Secret 与本地同名文件；更换 `MCP_OWNER_KEY` 不等于撤销所有既发 MCP grants，应另行撤销旧连接授权。Windows 的文件安全依赖目录 ACL，`mode=0600` 不替代 Windows ACL。

## 故障和成本

Google、Cloudflare 或 ChatGPT 功能与配额可能变化，按实际控制台处理。本项目不购买套餐、不提供故障即时通知，也没有自动日历读取或每日 GPT 报告。每指标最多 20 页，重复页令牌或超预算明确失败。细粒度记录增加 D1 存储和读写量；完整睡眠会话也会占用空间。

常见 OAuth Origin、CSP、Cookie、网络代理和分页问题见 [踩坑与排障](踩坑与排障.md)。既有部署的效果与尚未验收项见 [效果与验收记录](效果与验收记录.md)。
